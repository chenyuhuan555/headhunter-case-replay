# 猎头卡单复盘

首批推荐被退回后，下一步是换人、补证据，还是重新对齐岗位？录入岗位条件、首批人选的脱敏经历和客户原话，查看建议下一步，编辑或复制追问，然后回填客户答复与最终处理。填写退回和澄清日期可计算自然日差；是否在澄清前重搜由顾问记录。

## 运行

在项目目录运行 `node serve.mjs`，访问 `http://127.0.0.1:4398/`。服务端读取 `DEEPSEEK_API_KEY` 环境变量。未配置时仍可使用本地规则。

运行 `node --test` 检查建议的证据边界、本机存储、日期计算和演练回放。

按规则生成时，页面在本机匹配职责范围、项目责任、行业经验、到岗和预算等线索。主动选择「用 DeepSeek 分析」时，服务端只向 DeepSeek 发送岗位条件、人选经历和反馈原话，不发送岗位代号、后续答复或日期。请先脱敏。服务端拦截可识别的手机号和邮箱，并核对模型引用是否出自输入。无法取得可用结果时，会显示本地规则建议。建议不能自动改岗位或判定人选。

复盘记录保存在当前浏览器和站点地址下，不跨设备同步，清除浏览器数据会删除记录。「案例演练」保留三组虚构案例，与业务记录分开。

私有站点可用 `node server/build-worker.mjs` 生成 Worker，部署时在服务端配置同名密钥。分析接口需要站点登录身份。模型按 [DeepSeek API 文档](https://api-docs.deepseek.com/api/create-chat-completion/) 调用。

试用时先用脱敏旧单隐藏后续答复，比较建议有没有提前问到关键问题；再用新单观察澄清时长和澄清前是否重搜。日期差是实际记录，不代表节省的时间。
